# Résumé import flow

Implemented in the shared `SpecManager`, available during onboarding and in My Info on `feat/functionality-improvements`. It uses the copied processor inside the monolithic BE. See the [BE scanner contract](https://github.com/SMU-GoodEyeDeer/Jobtology-BE/blob/feat/functionality-improvements/docs/resume-scanner.md) for endpoints, limits, retention and deployment details.

1. **이력서에서 가져오기** checks the authenticated BE's runtime-supported formats. The input supports those formats only, up to 10 MiB, with a **three-page PDF limit**. The file is uploaded as raw bytes without its filename. A loading state supports cancellation. A separate opt-in checkbox enables **PDF-only paragraph AI extraction**, using the existing configured Luna/OAuth connection. Non-AI scanning retains the other formats.
2. The BE processes locally and removes source/temp artifacts before AI starts. Ordinary scanning makes no AI call. With consent, the new `/me/resume/analyze` stream performs one structured extraction per paragraph block, with four concurrent calls, no classifier and no automatic retries. Limits are 64 blocks/12,000 code points, 30 seconds per call/120 seconds for AI, and 200 total entries. Progress and suggestions appear as results arrive; cancellation or partial errors preserve received suggestions. Neither path automatically writes the profile.
3. A split view shows a sanitized HTML preview (or extracted text) and suggestions. Mobile uses **추출한 원문 / 제안** views. Source buttons and suggestion actions are keyboard accessible; **원문 근거 보기** selects, scrolls and highlights the exact span, including repeated quotes and Unicode. HTML uses a scripts-disabled sandbox iframe and network-blocking CSP; source CSS, external links/resources and event handlers are stripped in BE. Ambiguous anchors fall back to the text view. Missing PDF text shows an OCR notice and affected pages; OCR is not available. Preview/text remain only in component memory and clear on finishing/navigation/logout; crash file leftovers are swept after 15 minutes.
4. **검토하고 추가** switches the shared spec dialog to an editor with canonical candidates and the exact source quote. Desktop separates skill search from experience details; phones use a full-screen layout with save actions kept visible. Saving, cancelling, or pressing Escape in the editor returns to the same scan; the next entry requires its own experience-level choice. Closing the review dialog clears the scan. Category, issuer, scores, dates, evidence and skill choices remain editable. Neither file mentions nor an AI suggestion establish proficiency or credential validity. Existing-competency overlap is shown; no existing entry is overwritten or automatically merged.
5. Full-document extraction categorizes and reads multiple education, certificate, test, project, work, skill and other entries per paragraph. Fields must occur in the quotation. Partial dates stay verbatim in `imported_fields` and do not become invented day-level dates. Education/other entries need no proficiency and grant no competency credit. **역량을 못 찾겠어요 · AI 도움** remains a separately consented fallback for an editable selected passage. Both paths mask common email/phone patterns, but users must remove other private information themselves. Returned IDs/spans are validated; modified text must map to an exact unambiguous original quote. Unavailable AI/quota leaves direct selection usable.
6. Each confirmed record uses normal optimistic-version/idempotency/save/readback behavior, appears immediately with current-goal matching feedback, and is marked saved in the review list. A lost save response uses the same original operation key/version on retry. Successful save followed by failed GET retries only the GET. No bulk replacement occurs. Rerunning analysis applies changes; existing roadmap progress remains preserved.

`SpecDetails` includes `DOCUMENT_IMPORT` and typed `document_evidence` (document hash, parser version, block identity/hash, quote, Unicode code-point span, method). It is self-reported source context, not a verified qualification. Imported quotes remain visible when editing saved specs. O*NET identities remain separate from NCS, and Korean labels retain the existing translation/attribution notices.

The current scanner supports all five spec categories, literal NCS/O*NET aliases, explicit TOEIC/TOEFL/IELTS numeric results and manual review of any text block. It does not infer date precision, verified credentials, degree requirements or production experience, automatically edit education/profile fields, run OCR or retain original files. Real legacy HWP/DOC template accuracy and real-LLM résumé accuracy need further evaluation. HWP/DOC formats are advertised only when the BE discovers their native runtimes.

Tests cover Unicode/repeated anchors, malicious text rendering, explicit AI consent, contact masking, cancellation/stale responses, unavailable/quota behavior and the shared scan → editor → confirmed save → full readback path, including successive entries, Escape/back behavior, focus restoration and dismissal blocked during saves. The BE covers real synthetic format parsing, session/CSRF checks, limits, timeouts/process termination and temporary cleanup. Browser review uses synthetic data and a local disposable service; no production résumé/account was changed.
